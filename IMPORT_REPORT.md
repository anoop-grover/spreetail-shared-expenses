# IMPORT_REPORT.md

## Import Report Status

The assignment requires an import report generated after processing `expenses_export.csv`.

At the time of implementation, the referenced `expenses_export.csv` file was not present in the working repository. Because the file contents were unavailable, no CSV-specific import report could be generated truthfully.

The application has been implemented to automatically generate an import report whenever a CSV is uploaded and processed through the import workflow.

No anomaly records, row counts, or import actions were fabricated for documentation purposes.

---

# Import Workflow

The application executes the following workflow:

1. Upload CSV
2. Parse Rows
3. Normalize Data
4. Validate Records
5. Detect Anomalies
6. User Review
7. Import Approved Records
8. Generate Import Report

---

# Report Data Generated By The Application

Each import session stores:

* Import Session ID
* Source Filename
* Import Timestamp
* Import Duration
* Total Rows Processed
* Rows Imported
* Rows Skipped
* Total Anomalies Detected
* User Actions Taken
* Imported Expense IDs
* Generated Audit Records

---

# Anomaly Information Recorded

For every detected anomaly the system records:

* Row Number
* Anomaly Type
* Severity
* Description
* Original Data
* Resolution Action
* Final Status

---

# Example Report Structure

The following illustrates the structure produced by the application.

```text
Import Session: <session-id>

Rows Processed: X
Rows Imported: Y
Rows Skipped: Z

Anomalies Found:
- Duplicate Expense
- Invalid Amount
- Membership Violation

Actions Taken:
- Merge
- Ignore
- Skip
- Import
```

This example demonstrates report structure only and does not represent the contents of the official assignment CSV.

---

# Current Limitation

A final assignment-specific import report can only be generated after the official `expenses_export.csv` becomes available and is imported through the application.

No code changes are required once the file is provided.
