# Import Report

## Import Summary

This report documents the behavior of the CSV import system implemented in the Shared Expenses Application.

The import framework supports:

* CSV Upload
* Data Validation
* Anomaly Detection
* Review Actions
* Import Reporting
* Audit Logging

---

# Import Workflow Executed

```text
Upload CSV
   ↓
Parse File
   ↓
Validate Records
   ↓
Detect Anomalies
   ↓
Review Results
   ↓
Apply User Decisions
   ↓
Generate Report
```

# Supported Anomaly Detection

The importer validates uploaded data and records detected issues.

Examples include:

* Duplicate Records
* Missing Required Fields
* Invalid Amounts
* Invalid Dates
* Unknown References
* Data Consistency Issues

Detected anomalies are attached to the import session and presented for user review.

---

# Review Actions Supported

The following actions are available when anomalies are detected:

| Action    | Description             |
| --------- | ----------------------- |
| merge     | Merge duplicate records |
| keep_both | Retain both records     |
| ignore    | Ignore detected anomaly |

No potentially destructive action is automatically applied without review.

Each import session stores:

# Audit Trail

Import-related operations generate audit records.

Examples:

* Import Created
* File Parsed
* Anomaly Detected
* Review Action Applied
* Import Completed

This allows import activity to remain traceable and reviewable.

---

# Design Principles

The import framework follows three principles:

## Transparency

Detected issues are surfaced to users.

## User Control

Users decide how anomalies should be handled.

## Traceability

Import decisions remain associated with the import session and audit history.

---

# Conclusion

The Shared Expenses Application implements a review-first CSV import framework that supports anomaly detection, user-controlled resolution, import reporting, and audit logging while maintaining data integrity and traceability.
